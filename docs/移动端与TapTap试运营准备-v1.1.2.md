# 移动端与 TapTap 试运营准备 · v1.1.2

更新：2026-10-10。本次完成手机网页的操作与资源适配；Android 安装包、TapSDK、平台资质和提审尚未接入。运行仍是七章战役，42 关扩展仍处于设计交付阶段。

## 手机玩法

- 竖屏适合单手指挥，横屏保留中央地图；窄窗口与 1200px 内的粗指针设备使用紧凑 HUD。显示与输入分别判断，鼠标仍可直接下令。
- 单指拖动、双指缩放；轻点部队后点目标，预览路线、能源、伤害与反击，再确认。拖动、双指、取消、旋转屏幕或状态改变不会把预览变成指令。
- 地图格长按约 0.65 秒查看情报，保持原有部队选择；只能显示当前观测部队和最后已知建筑，遵守战争迷雾。
- 设施按钮、单位指令说明、属性和仓库头像可长按查看；松手不会触发订单。鼠标继续使用 1.5 秒悬停说明。
- 单位面板默认收起详细属性，仍保留移动、攻击、占领和技能按钮；“能力 / 状态”打开详情。同格有设施时仍能进入管理与生产。
- 设施管理为可滚动抽屉；确认面板、抽屉、小地图与单位面板互相避让，不依赖 `:has()`。底部“地图”打开小地图、缩放、总部和全图定位。
- 使用动态视口高度、刘海与底部手势区安全距离；核心按钮 44px 起，表单字体 16px。旋转屏幕保留镜头中心和格子的像素尺度，并取消待确认指令。
- 切到后台保存完整事务并暂停；返回仍保持暂停，点击“继续作战”恢复。手动暂停也不会因返回页面自动解除。手机默认快速动作节奏，已保存的设置优先。

## 资源与性能

`assets/mobile/units/` 提供全部 198 张 WebP：38 立绘、38 头像、38 缩略图、42 前视与 42 后视 Q 版。前后朝向和两栖海陆形态完整保留。

对应 PNG 合计 54.52 MiB，WebP 合计 8.04 MiB，文件体积减少约 85%。手机优先使用 WebP，加载失败尝试原 PNG，然后保留已有的棋盘矢量替代图。仅编码发布图，不修改原画；本次抽查了步兵、驱逐舰后视和轰炸机立绘。

地图复用连贯地形的 SVG 缓存，地形改变时重建；已探索与可见格使用索引查找。手机去除 HUD 的实时背景模糊和海面持续动画。未测量真实设备帧率，文件体积缩减不等同于同幅度的帧率提升。

重新编码可用 `npm run assets:mobile`，需本机 Sharp，或将环境变量 `SIX_REALMS_SHARP_PATH` 指向已有 Sharp 模块。游戏正常运行无需该依赖，也无需构建。

## TapTap 发布路线

建议先选择 **Android 本地 WebView 安装包**，复用现有 HTML/CSS/JS/SVG，安装包内携带游戏运行文件。Android 官方的 [WebViewAssetLoader](https://developer.android.com/develop/ui/views/layout/webapps/load-local-content?hl=zh-CN) 可用 HTTPS 形式加载应用内资源，适合这类静态网页；封装时保持稳定的本地来源和包名，启用 DOM 存储，并实现原生文件选择、存档导出与应用生命周期处理。

这是一项后续工程建议。本次没有生成 APK、选择正式包名或创建平台游戏。安装包不应只加载 GitHub Pages，试玩需验证断网时地图、立绘与音效仍可用。

TapTap 也提供小游戏路线。[官方开发说明](https://developer.taptap.cn/minigameapidoc/quick-start/guide/dev/) 使用 `game.js` / `game.json` 入口和平台 Canvas、触摸、音频与缓存接口。由此推断，本项目现有 DOM/SVG 界面需要独立兼容性验证与适配，不能把网页压成普通 ZIP 后视为已完成接入。

根据 [TapTap 小游戏创建文档](https://developer.taptap.cn/minigameapidoc/quick-start/guide/creation-improvement/)，上传包需由其打包工具生成，首包限制约 60M+，需接入 TapTap 登录；开放测试或上线前在开发者后台完成相关资质审核。普通手机游戏的测试流程见 [新建和管理游戏](https://developer.taptap.cn/docs/store/release/publish/create-game/)，测试阶段需要上传 APK 并完成对应审核。平台要求以提交时的开发者后台为准。

无论选择哪条路线，打包只收集运行文件；`assets/units/sources/` 与 `direction-sources/` 约 174 MiB 的绘画源文件，以及 `legacy/`、文档、报告和 `.git/` 都不应进入手机包。

## 试运营下一步

1. 确定 APK 或小游戏路线及正式包名 / 平台游戏 ID；保持存档来源稳定。
2. 完成对应封装、平台服务与文件导入导出，生成可签名的测试包。
3. 使用真实 Android 手机测试 320–430px 竖屏、横屏与刘海，至少一台较低性能设备；网页路线另测 iOS Safari。
4. 重点试玩生产、部署、驻守与建筑血条、海陆转换、占领、四难度 AI；测试首次加载、旋转、切后台、重启、升级和存档恢复。
5. 录制真机游玩视频和截图，补齐图标、介绍、开发者信息及后台要求的资料，再进行内部测试和提交审核。

建议首轮 20–50 位玩家、标准难度、小地图，记录“完成首个回合 / 生产第一支部队 / 完成首次占领”的比例、误触率、存档恢复成功率、退出原因和设备型号；当前未加入远程分析 SDK，这些数据可先通过自愿反馈收集。

## 验证与兼容性

入口 `npm run test:mobile`。专项包括七种视口的真实控制器模拟、误触与长按、双指、旋转、相机引用、同格设施、迷雾、后台保存与暂停、WebP 全型号及 PNG 回退、资源覆盖和 CSS 布局约束。另跑现有规则 / 界面 / 美术 / 资源回归。

浏览器保存的权限设置阻止工具访问 `http://127.0.0.1:8877/`，本次未进行真实浏览器截图或手机验收；模拟 DOM、CSS 约束和离线图片抽查不能替代实机布局、听感与帧率测试。

存档 schema、规则版本、本地键、设施迁移和七章进度保持原值。新界面设置沿用 `six-realms-ui-v08`，只有未设置的手机默认动作节奏改为快速。
