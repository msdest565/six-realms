# 《六域：边境交锋》多方对战规则 v0.7

日期：2026-10-08。适用自由战役的2—6方。剧情七关仍为v0.6的双方对局。基础动作、HP、装甲、伤害与技能采用v0.5，资源名称采用[能源规范](能源系统设计-v0.7.md)。本文件明确覆盖多人身份、胜利、出局、队伍、视野和时序。

## 1. 玩家、队伍与控制者

玩家ID固定为P1…P6，neutral为中立建筑归属，不是第七位玩家。参与人数包括人类和AI，最大6；每席独立资金、能源、24编制、己方回合计数、单位、设施订单和库存。union/red只作为现有美术主题，不作为玩家ID、队伍ID或敌我判定。

| 关系设置 | 人数 | 地图席位分组 | 固定循环中的顺序示例 |
|---|---:|---|---|
| 各自为战 | 2—6，按规模限制 | 每席一队 | P1→P2→…→PN |
| 2v2 | 4 | A={P1,P2}，B={P3,P4} | P1→P3→P2→P4 |
| 3v3 | 6 | A={P1,P2,P3}，B={P4,P5,P6} | P1→P4→P2→P5→P3→P6 |
| 2v2v2 | 6 | A={P1,P2}，B={P3,P4}，C={P5,P6} | P1→P3→P5→P2→P4→P6 |

双方对战相当于两个单人队伍。队伍与出生席位在开局前固定；本版不允许战中结盟、退出联盟、转赠单位、交易建筑或共享资源。队友共享当前视野，但只控制自己的单位和经济。

默认玩家样式为：P1绿色圆形、P2红色三角、P3蓝色方形、P4橙色菱形、P5紫色五边形、P6青色六边形，均显示P序号；中立使用灰色。队伍由边框与A/B/C标签表示，玩家颜色仍保持不同。不能仅靠颜色识别敌我，也不能把两个使用同样美术主题的玩家合并。

控制者可为local_human、ai，未来可为remote_human。控制者断线或离开输入界面不直接等同投降；联网超时与接管由后续联网版本定义。本版实现目标为单人对AI与本地轮流操作，先使6方规则与状态可运行。

## 2. 敌我、占位、攻击与修复

所有单位统一一格一单位，包括飞机、舰船、盟友和己方部队；不能穿过任意已占格，包括队友。建筑与一单位共格合法。队伍视野共享不意味着可借队友单位跨越阻挡。

不能攻击同队单位或同队建筑，不能占领自己或队友已经拥有的建筑。任意型号可占领敌对或中立建筑，包括总部、地基、能源设施和废墟。建筑本格有任意敌对单位时必须先清除；同队驻军不会阻挡相邻占领中立/敌对建筑。若建筑本格是盟友飞机，也仍占一格，其他单位不能移入。

工程车修复仅作用于所属玩家的单位和建筑，不跨玩家修复队友，以保持目标修复额度按所有者己方回合定义。技能次数、修复40 HP、不自修和目标每所有者回合仅受修复一次等条件保持v0.5。此限制只影响修复目标归属，不取消任意单位占领能力。

建设范围只由自己的完好总部/城市提供；同队城市不直接提供建设半径。盟友单位与己方建筑地基可以共格，但敌对单位占格禁止施工。每玩家可同时一个新建工程；生产、升级、部署分别使用自己的资源、设施ID、库存和编制。

## 3. 回合、轮与刷新顺序

回合顺序由房间确定一次。各自为战沿地图席位循环，随机选择起始席；队伍局按上表示例交错队伍，再随机选择起始席。玩家与地图席位绑定可在开局前交换，开局后不重洗顺序，也不每轮旋转先手。

全局轮开始时记录本轮尚需行动的存活席位列表。一个席位开始并完成自己的回合后，从列表删除；尚未行动席位如果出局也删除。列表空时轮数+1，以固定循环重新形成下一轮列表。出局不会让其他玩家多获得一个回合，也不会重复结算收入。

己方回合开始严格执行：己方计数推进及到期/冷却 → 自己建筑收入 → 建设与升级推进 → 单位生产推进 → AP/移动/反击/修复额度刷新并应用本回合负面效果 → 当前视野与胜负更新 → 行动阶段。第一次回合也正常收取收入，8座初始建筑使每方第一次可操作资源为720金钱/74能源。

一次行动事务完整结束后才交给下一输入，事务顺序为动作合法检查 → 扣款/AP与效果 → 伤亡、订单/库存及归属变化 → 本次动作对应的合法反击及伤亡 → 总部出局与资产清理 → 视野/登记表 → 胜负 → 日志/保存。占领不引发周围单位自动反击，只有直接攻击事务包含反击。

## 4. 反击与跨多个敌方回合的状态

每单位反击额度仍是**连续两个自己回合开始之间最多一次**，即使期间遭受五个不同玩家攻击也不会按攻击者刷新。开局额度1，部署新单位额度1；反击不耗AP与能源。

例如P1防空车在P2回合对直接攻击者合法反击，消耗额度并按减伤后的伤害×1.5；P3再攻击该车时，本周期不能再次反击。P1下次开始才恢复。不能因为换攻击方就重新获得150%反击。间接炮击没有反击；射程、视线、存活和目标权限继续满足基础条件。

所有冷却与“下一己方回合”“到下次己方开始”为单位所有者的回合计数。P4受到电子战后，其下一次开始AP为1，后续恢复回合的抗重复控制标记仍按P4自己的计数判断；P5/P6的回合不会使其提前过期。突击步兵掩体、重坦锚定、扫描效果等也不按全局轮数提前或重复刷新。

## 5. 胜利A：占领总部

每玩家原始总部是开局记录的永久实例ID。**被敌对玩家成功占领原始总部，原始所属玩家立即出局。**攻击使总部HP归零只产生废墟，不直接出局；占领该总部废墟同样触发出局。其他城市、后来抢得的总部与其他建筑不替代自己的原始总部。

两方局中，占领对方总部即使对方出局且只剩一个队伍，立即获胜。三至六方局中，占领一个对手总部使该对手出局，整个战局继续；最后只剩一个存活队伍时，该队伍获胜。队伍局只要仍有一名队员存活，队伍继续参战；已出局成员不能被重新激活。

| 情况 | 结果 |
|---|---|
| P1占领P2原始总部，其他敌对席位仍存活 | P2出局，P1不立即获得整局胜利 |
| P2原始总部HP变0但仍归P2 | P2仍参战，原始总部仍可占领 |
| P2已抢得P3总部，但自己的总部随后失守 | P2出局，已出局P3不复活；资产按下节处理 |
| A队P1出局、P2仍存活 | A队继续，P2不能用P1原始总部作为复活点 |
| 所有B/C队成员均出局，A仍有成员存活 | A队获胜，不要求再收集全部中立建筑 |

## 6. 出局与投降的资产处理

先完成导致出局的占领，再一次性清理原始玩家。刚被占领的总部已经归新所有者，保留其当前HP、类型与等级，不被后续清理再改中立。

出局玩家的全部存活单位从地图移除；资源归零；全部生产、升级、施工订单与库存取消，不退款、不交给占领者；其余仍归该玩家的建筑变中立，保留永久ID、类型、等级与HP。该玩家施工中的地基转为Lv.1、完整HP上限、0 HP建筑废墟，原施工订单取消；完工建筑废墟仍为废墟。

清理后不会把军队传送给夺取者，也不会删除建筑胜利目标。这样保留可争夺的战场资产，同时避免夺取一个总部就免费继承24单位。原玩家建筑内的其他玩家单位不受资产清理伤害，继续单格占位。

投降仅使发起玩家出局，队友继续。队伍要全部投降，分别确认各自的投降操作；不允许一位队员替其他人投降。任一胜利模式中，若其他所有敌对玩家已投降/出局导致只剩一个存活队伍，该队伍获胜。

## 7. 胜利B：占领全部建筑

该模式下占领总部只转移建筑，不直接使原玩家出局。原玩家仍能使用剩余部队、建筑、订单与资源，且可以反夺自己的原始总部。不能偷偷叠加“总部失守淘汰”条件。

每次完整归属变化、地基创建、出局资产清理后，检查全局建筑登记表：若所有建筑实例的owner都属于同一个存活队伍的成员，该队伍获胜。各自为战时只有一个成员，相当于一个玩家拥有全部建筑。队伍之间不需要把建筑再统一转到队长名下。

登记表包含初始己方/敌方/中立建筑、后来新建的地基、HP归零的废墟和投降后转中立的建筑。没有主动拆除，总部不能新建。目标总数从12N+1开始，新建地基成功时增加；损毁与出局不减少目标总数。能源点标记不计建筑数，尚未施工的空地不计。

若三队中C投降，C余下建筑变中立；A不能只统计A/B资产而忽略C遗留的海上能源平台。若最终B也投降只剩A，按投降胜利直接结束，无需继续收集所有中立目标。

## 8. 无兵状态、和局与长期对局

失去所有单位不自动视为出局或对方获胜。只要有库存、订单、可用生产设施、可继续建设的总部/城市或有效施工，仍可能恢复作战。AI在无可执行操作时结束自己的回合；玩家可手动结束或选择持续自动结束，仍结算该玩家每轮自己的收入和订单，不把所有权提前转中立。

允许所有存活人类玩家同意和局；AI在一致的人类和局选择下接受，作为单人结束长期对局的选项。没有强制轮数或时间判负。

自动僵局只在全体存活玩家都满足下列条件时判和：无存活单位、库存与单位订单；无完好已完成生产设施；无有效在建城市/生产设施；并且无任何完好总部/城市能够在控制半径内找到合法生产设施建设地形与空建筑位。最后一项为保守的恢复可能检查，忽略临时单位占格和当前视野限制，避免把将来可恢复的局面误判为和局。不能直接照搬只检查“没有单位和生产建筑”的旧简化判据。

单个受困玩家保留身份与建筑，只有总部模式的原始总部占领或主动投降才使其出局。胜利始终来自选定的占领条件或其他队伍退出，不新增消灭单位的胜利选项。

## 9. 迷雾、日志与观战

队伍共享当前可见格及探明地图；经济库存、设施订单与单位操作权限仍分别归各玩家。队友之间可查看当前部队状态用于配合，不能借此读取敌方隐藏状态。

初始地图地形、建筑位置和原始总部身份在地图预览中公开，敌军移动与后来新建筑位置在游戏迷雾下保密。全建筑模式的全局登记总数与本队已拥有数公开；未知目标只显示数量，不以坐标箭头泄露未探明建筑。已探明建筑离开视野后显示最后确认信息与“未确认”标记，不能继续更新敌方隐藏归属。

日志按阅读者视野过滤。视野外的攻击、部署、修复或生产不公开单位ID、坐标、型号和HP；涉及自己单位的受击与自己建筑的损失则正常告知。本地轮流操作切换玩家时先显示遮挡交接页，再应用新的队伍视野，不能继承上一位玩家的选中单位、路径预览、敌方定位或完整日志。

出局者默认只能观察存活队友共享视野；各自为战的出局者可退出或观看迷雾遮挡的公共回放，不能在未结束对局中直接获得全图敌军信息。整局结束后才允许完整回放。

## 10. 保存与实现数据

至少保存players[ID]的teamId、controller、alive/eliminated、resources、ownTurnIndex、originalHqId、cap占用；固定turnOrder、本轮pendingPlayers、当前actor、globalRound；逐玩家视野/探明记录；全局单位/建筑及永久ID、订单/库存、地基；各单位AP、累计移动、道路资格、反击、技能、修复和状态；地图实际布局、seed、生成器版本、来源与哈希；选定胜利模式与结果。

胜负结果记录winnerTeamId、相关成员、trigger与本次触发建筑ID。总部归属变化、出局清理、登记表更新与结果保存必须是同一不可分割事务；不能在中间阶段存档后重复继承资源或复活单位。

读取旧双方对局可将union/red分别映射为P1/P2，同时保留factionStyle。剧情模式保留其自己的union/red场景契约，不因自由战役迁移而破坏已交付七关。资源字段迁移由[能源规范](能源系统设计-v0.7.md)统一规定。
