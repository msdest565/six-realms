## 1. 音频风格定案

声音表达“明亮海风中的机装少女联队”：海风与港口是世界底色，机械扣合使武装可信，短而清透的晶体音色表达潮晶能源和联队终端。少女的魅力首先来自形象、姿态和可靠的协作；不要求玩家每次点击都听角色讲话。

| 层次 | 具体听感 | 使用边界 |
| --- | --- | --- |
| 人物与轻装 | 清楚的鞋底落点、短布料声、背包和枪机轻碰 | Q 版可略有轻巧感；不做卡通滑倒、尖叫或每步口号 |
| 机装 | 短马达、液压、金属卡扣、炮架回位 | 重型靠节奏、瞬态和机械余韵表达重量；不靠持续轰鸣和不断增大音量 |
| 潮晶终端 | 木琴／玻璃琴质感的两三音、短合成泛音 | 占领、修复、扫描等信息反馈；不是魔法攻击或无限能源的证明 |
| 海洋与城市 | 柔和浪声、海风、远处小型设施运行 | 不添加没有画面或玩法依据的群众惨叫、战场广播 |
| 战斗 | 枪炮释放、弹体通过、机装受击分清先后 | 清楚而克制；小手机扬声器能听到中频主体，低频尾巴不压住下一条指令 |
| 音乐 | 原创旋律、钢琴／木质拨弦、轻弦乐、适量电子脉冲和克制打击乐 | 保留恢复灯光与共同供给的希望感；危机段有压力但不全程重金属轰炸 |

统一听觉标记为“接线扣合 + 三音上行确认”。建议原创三音关系采用主音、二度、五度，节奏约 0／80／180 ms；正式作曲时定调和校验旋律原创性。普通 UI 只取第一个短音，部署取前两音，占领取三音，终局用完整乐句。不要让每个动作都响完整标记。

人物为明确成年女性，声音可明快、冷静、爽朗、沉着，不使用幼儿化声线。敌我共享装备技术，兵种声音一致；阵营区别只体现在公开界面确认音和少量曲风配器，不以难听的敌方声音替代角色设计。

## 3. 声画时轴和事件契约

音频听结果，不推演规则。接入顺序为“核心提交成功 → 生成观察者可见事务 → 动作／声音共享 marker → 表现结束”，失败指令只给已有公开失败原因的 UI 提示。预览射程、按住按钮或点击技能图标，不提前播放攻击和技能成功声。

### 3.1 三档独立时轴

采用动作设计的独立时轴；下表单位为 ms，时间从本次表现开始计算。三档不通过提高音频 `playbackRate` 来改变音高。`prepare` 为预备，`launch` 为武器释放，`impact` 为命中或成功确认，`settle` 为表现收尾。支援、接管、部署的 `impact` 不表示伤害。

| 动作 | 标准 launch／impact／settle | 快速 launch／impact／settle | 减少动态 launch／impact／settle |
| --- | --- | --- | --- |
| 直射，包括普通枪炮与穿甲 | 140／300／620 | 50／100／220 | 0／40／120 |
| 导弹／鱼雷 | 180／480／760 | 65／140／260 | 0／40／160 |
| 间接炮击、轰炸 | 180／520／820 | 65／160／280 | 0／40／160 |
| 定点狙击（含准备瞄准） | 340／500／820 | 100／150／280 | 0／40／160 |
| 部署 | 0／120／340 | 0／40／140 | 0／0／100 |
| 据点接管 | 0／260／440 | 0／90／160 | 0／0／100 |
| 构筑掩体 | 120／430／620 | 40／130／220 | 0／40／120 |
| 锚定防线 | 100／360／620 | 35／110／220 | 0／40／120 |
| 主动扫描 | 100／380／640 | 35／115／220 | 0／40／120 |
| 应急修复 | 120／430／720 | 40／130／250 | 0／40／160 |
| 链路干扰 | 100／360／640 | 35／110／220 | 0／40／120 |

移动只在真实可见路段的 `contact` 落点发声。步兵每格标准／快速／减少动态为 180／80／40 ms；履带与炮装 200／85／40，轮式与步足 170／75／40，舰装 190／80／40，固定翼 140／60／40，旋翼 170／75／40。段收势为 60／30／0 ms。单次表现最长 1400／650／400 ms，超长路线压缩格间等待，实际路径不改变。

步兵标准 contact 在格间时轴的 0.28／0.72，快速在 0.5；T／R／W／G 的标准与快速机装 contact 为 0.5。N／A 只用段起止，H 使用单段持续包络，不逐格造脚步。实际接触发声标准最密 120 ms、快速最密 160 ms；减少动态统一省略逐格接触。音频可按第 4 节密度预算进一步稀疏采样合法 contact，只减少重复听感，不改变路径和结果。不在每帧或每个插值坐标制造新声音。音效作者按 marker 间可用时间提供原版、短版和受控淡出，不因播放器加速导致角色声线或炮声升调。

- 标准攻击：`prepare` 轻枪机／炮架；`launch` 发射主体；`impact` 受击；`settle` 必要的回位。弹体通过声只在确实存在轨迹且可见时使用。
- 快速：保留 launch 和 impact，省略独立装填、长弹道哨音、长回位；发射音选 70—140 ms 短版，命中音选 100—180 ms 短版。
- 减少动态：静态姿态和短提示对应同一结果；保留可听的释放／命中，淡出尾音，不使用空间扫过或夸张连续爆破。
- 纯跳过动画：从已经提交且可见的事务产生 80—160 ms 关键命中或成功确认，不补全整条动作；退场用退场短音替代普通命中。批量生产／出库可合并提示，但地图和列表结果必须完整。
- 关闭声音：零声音；字幕、数字、状态标记仍完整。声音从不作为判断命中、获胜或技能成功的唯一渠道。

### 3.2 建议调度数据

以下是待开发契约，不是当前已有 API。`phase`、合法位置和结果由观察序列提供；音频层不得读完整隐藏战场来补齐。

```json
{
  "transactionId": "battle-session:revision",
  "eventId": "observed-event-index:instance-id",
  "phase": "impact",
  "cue": "hit.armor",
  "mode": "fast",
  "position": "observed-point-or-null",
  "priority": 80,
  "audible": true
}
```

以 `transactionId + eventId + phase + cueRole` 去重。一次原子攻击可能有两个事件：攻击命中和合法反击命中；分别发声，不能把反击误判为重复。手动部署与同一次核心自动出库指向相同实例时只确认一次。若语义 marker 已触发，再切换快速或跳过，不能再次播放同一提示。

随机变体只影响听感，不影响游戏随机种子。建议使用音频独立随机源与不连续重复的 shuffle bag；缺变体时安全回退，不重试发出同一声音。

## 4. 文件目录、命名和声库清单

建议未来目录为 `assets/audio/sfx/`、`assets/audio/ambience/`、`assets/audio/bgm/`、`assets/audio/voice/zh-CN/`。本轮没有创建这些音频文件。

命名示例：`sfx_weapon_cannon_medium_launch_v01.wav`、`sfx_hit_armor_short_v02.wav`、`sfx_skill_scan_resolve_v01.wav`、`bgm_c03_port_base_loop.wav`。源文件统一 WAV；运行版扩展名由导出与设备兼容方案决定。`v01—v03` 是听感变体，`_short` 是保持音高的短尾版，`_loop` 标明可循环。不要用“最终版2”“新新的炮声”一类名称。

每个文件在清单登记：cue key、源／运行文件、变体、时长、是否循环、声道、建议分组、相对增益、优先级、marker、授权／制作来源、解码后预计内存。以下时长是设计目标，不是现成素材检测结果。

四个适配差异必须在开发任务中明确：

1. 当前六种专门防空在 `projectileFamily()` 中统一走 missile，新形象天幕四联炮与云帆单炮应改表现为短连炮；这是表现映射修改，防空反击机制不变。
2. 当前潜锋统一走 torpedo，而数据说明其可对陆使用巡航导弹；新版目标可在合法可见的目标为陆地时使用导弹表现。目标域不公开时回退中性命中，不查询隐藏域。
3. 当前普通非步兵侦察／工程／电子战攻击大多走 shell。新版允许轻自卫枪表现，与实际弱攻击结果一致；要同步美术武装，不能单换成能暗示新增治疗、EMP 或穿甲能力的声音。
4. 当前长钉普通攻击走 shell，定点狙击走 rail。新世界的长磁轨炮允许二者共用 rail 声纹和直射外观，普通攻击不获得定点狙击的额外伤害；技能仍有独立准备时间与确认标记。

若前期只接新外形，仍沿用旧合成映射，应把这些差异登记为表现待办，避免宣传为已完成整套音画统一。

## 6. 八个主动技能

技能采用共用 prepare 和 resolve 词干，攻击类仍走 launch／impact 时间；每个成功 marker 只发一次。音频 UI 的“冷却”是重复提示限流，游戏技能冷却仍按现有回合规则。

| 技能／key | prepare／launch | impact／resolve | 目标时长、循环及规则边界 |
| --- | --- | --- | --- |
| 穿甲弹 `pierce` | 棱镜弹仓锁定，短清透充能 | 金属穿透脆响 + 目标正常短受击 | prepare 80—120 ms，impact 140—220 ms；2—3 变体，无循环；只解释忽略现有 10 点装甲 |
| 震荡弹 `shock` | prepare 炮架稳定；launch 抛射释放 | 一次偏低震荡 + 减速状态短提示 | impact 180—280 ms；2—3 变体，无持续低频；不是范围地震或眩晕 |
| 定点狙击 `sniper` | prepare 稳定臂扣合、单次锁定；launch 单束磁轨释放 | 尖锐但短的命中／穿透 | prepare 100—160 ms，impact 120—200 ms；2—3，无循环；不能给移动后的非法技能发声 |
| 构筑掩体 `entrench` | 哨兵展开掩体板和支撑 | 两次砂石／金属落锁 + 很轻确认 | 全套 180—320 ms；2—3，无循环；状态建立后不持续敲打 |
| 锚定防线 `anchor` | 磐石液压放下支架 | 四角固定汇成一次厚扣 | 全套 220—350 ms；2—3，无循环；不播放无敌护盾音 |
| 主动扫描 `scan` | 游隼／侦察机传感器转动 | 清透高低二音和短扫频 | 全套 180—320 ms；3，无循环；不按发现多少隐蔽敌军增加响声 |
| 应急修复 `repair` | 织补工具头／机械臂接近 | 短棘轮 + 接线成功双音 | 全套 200—350 ms；3，无循环；完成处发声，失效目标不播放成功音，不暗示复活 |
| 链路干扰 `jam` | 脉冲天线切换和短脉冲 | 短失谐纹理 + 清楚但轻的状态确认 | 全套 180—320 ms；3，无循环；失谐不尖锐，不跨整个下回合持续嗡鸣，不暗示人格操控 |

支援类采用动作设计对应的 `impact` 确认时刻。scan／jam／repair 三种电子音分别为稳定双音、失谐短纹理、机械工具＋双音，闭眼能辨识；不会因都带晶体色彩而变成同一个“叮”。同一技能若已有成功确认，不在 `settle` 再播放一条确认。

## 7. UI、接管、生产、FIFO 与对局状态

| cue key | 实际触发 | 时长／次数规则 |
| --- | --- | --- |
| `ui.select` | 单位／设施选择改变并成功 | 40—70 ms；3 变体；同一选择不重复 |
| `ui.open`、`ui.close` | 抽屉、详情、图鉴实际开关 | 60—100 ms；2；快速连续切换限 120 ms |
| `ui.confirm` | 普通公开设置或有效操作确认 | 70—120 ms；2；不与独立事务成功音叠加 |
| `ui.cancel` | 返回、取消选取 | 70—120 ms；2；与生产取消共用词根但降低强度 |
| `ui.invalid` | AP 不足、范围／资源／冷却等已公开失败原因 | 100—160 ms；2；全局最密 500 ms，同时显示具体文字 |
| `ui.focus` | 已知目标定位或地图聚焦完成 | 60—100 ms；2；拖动、缩放、划屏不每帧响 |
| `ui.tab` | 主分类／兵种筛选确实改变 | 40—70 ms；2；列表搜索输入不逐字符响 |
| `capture.commit` | 核心确实接管设施，在接管 impact | 220—340 ms；3 音标记；手动与自动同一设施事件去重 |
| `capture.loss` | 观察者获知自己设施易手 | 180—280 ms；下降短标记；未公开敌方设施不发声 |
| `produce.order` | 己方／合法可知设施排程成功 | 80—130 ms；机械登记单音；无“人物出生”音 |
| `produce.cancel` | 核心确实取消排程 | 80—130 ms；一次下降音；不与 ui.cancel 双响 |
| `produce.ready` | 己方产出进入可知库存 | 100—160 ms；双音；只表示整备就绪，不代表部署成功 |
| `deploy.reveal` | 实际部署实例出现，在部署 impact | 标准 140—220 ms，短版 80—130 ms；不能因库存排队提前播放 |
| `deploy.blocked` | 本地玩家第一次尝试出库获知部署格／编制阻塞 | 100—160 ms；限 600 ms；自动 FIFO 每回合失败不重复叫警报 |
| `fifo.batch` | 同一回合合法多实例出库的汇总 | 120—200 ms；建议前 3 个实例用 reveal，其余合并为一条批次短提示；每个实例仍完整显示 |
| `facility.construct` | 新设施建造被核心接受、实际完成分别显示 | 接受 80—120 ms，完成 160—240 ms；核心没有独立完成事件时不编造第二响 |
| `facility.upgrade.order` | 升级排程成功 | 100—150 ms；避免与升级完成混淆 |
| `facility.upgrade.ready` | 玩家合法获知实际升级完成 | 160—240 ms；一次；不因列表重绘重复 |
| `turn.own` | 合法己方回合开始事件 | 180—260 ms；稳定二音、居中；批量部署按核心事件位置排列 |
| `turn.other` | 公开回合交接 | 80—140 ms、低 4—6 dB；不播对方隐藏生产提示 |
| `pause.on`、`pause.off` | 用户暂停／恢复 | 60—100 ms UI 音；先暂停其他组，UI 可单独轻响；浏览器拒绝恢复时静默处理 |
| `result.win` | 核心已判胜／战役公开成功 | 2—4 s 原创收束；每场一次；优先于普通回合提示 |
| `result.loss` | 核心已判负／战役公开失败 | 1.5—3 s 克制下降，保留重整感；不用羞辱性嘲笑 |
| `result.draw` | 当前模式确实有平局结果 | 1.5—2.5 s 开放和声；没有平局规则不虚构判定 |

产出、出库、接管是不同结果。典型复合事务应为“移动接触 → 接管成功 → 实际 FIFO 显形”，不能同时响一团；攻击事务为“launch → impact → 实际合法反击 launch／impact → 新部署”。自动出库释放的格子尚未合法释放时，不能预告增援。

界面 hover 默认无音，以免桌面光标经过几十个六边形形成密集提示。手机点按只发一次提交／选择反馈，touch、pointer、click 多事件不重复绑定。长按查看、双指缩放和拖拽地图不播放攻击或选中语音。

## 8. 环境床与七章音乐

### 8.1 环境床

| cue key | 建议声床 | 循环目标／边界 |
| --- | --- | --- |
| `amb.land` | 海岸陆域柔风、远处草木、小小空间感 | 20—35 s 立体声无缝环；不依赖未见林地和敌军 |

同一时刻通常一个床；切换有 0.4—0.8 s 淡入淡出。设备吃紧时直接淡出旧床再起新床，不能长期重叠四个环境循环。循环边界无可闻突跳，不自动播放随机舰炮或敌军语音。环境关闭时环境节点停止；不只是把一堆循环调成零音量。

### 8.2 音乐曲目和配器

原创主题“把黎明送回六域”以简短上行旋律表现接线与灯光恢复。战斗音乐与同主题相联系，不让新设定变成完全不同的七个游戏。剧情角色不必在流程中存活，音乐也不依赖某个特定角色存活触发。

| 场景／章节 | 音乐名（候选） | 情绪、配器与速度建议 |
| --- | --- | --- |
| 主菜单／图鉴 | 《雾海的来信》 | 轻钢琴、木质拨弦、细弦；约 82—92 BPM，展示成年角色的日常气质 |
| 简报／整备 | 《出发前的接线》 | 主主题碎片、柔和电子脉冲、稀疏打击；约 88—100 BPM |
| C01 灯还亮着 | 《一盏灯的方向》 | 青绿田野感、明亮木琴和拨弦；约 96—104 BPM，教学段空出提示声 |
| C02 白沼的织补线 | 《织回光的线路》 | 钢琴、细工具节奏、清透晶体音；约 100—108 BPM，修复与节点连接 |
| C03 浪锋驶向盐湾 | 《向海风交接》 | 开阔弦乐、轻鼓和港口主题；约 108—116 BPM，爽朗但不做滑稽海盗曲 |
| C04 天空留下的路 | 《云间的坐标》 | 气流感合成器、拨弦、轻拍；约 112—120 BPM，侦察与重新联络 |
| C05 棱镜之下 | 《重甲之后的晨光》 | 稳重弦乐、短金属打击和有限低鼓；约 104—112 BPM，力量有秩序 |
| C06 风暴之前的海峡 | 《让航道保持呼吸》 | 舰装主题与航空主题交错、细电子纹理；约 116—124 BPM，紧迫但不过量 |
| C07 把黎明送回六域 | 《黎明共同供给》 | 完整主主题、联队节奏与明亮弦乐；约 120—128 BPM，结束回到温暖变奏 |
| 战后成功／失败 | 《灯再次亮起》／《仍有下一条路》 | 2—4 s 短结尾 + 可选 30—45 s 结算曲；失败不骤然刺耳断裂 |

每章基础循环建议 90—150 s，初期可共用 3 首战斗主题的地区变奏；正式版每章一套 3 层 stem：`base` 和声／主氛围、`pulse` 节奏／压力、`melody` 旋律／协作。三层同采样起点、同 BPM、同长度，循环点对齐；不要求运行时改变速度。

压力层由公开模式／回合、章节作者的明确节拍、玩家已知目标阶段驱动。禁止按隐藏敌军数量、隐藏敌方资源和未见生成的增援提高紧张度。普通战局无这些公开阶段时只播稳定基础与低强度 pulse，避免每打一枪切换音乐。

音乐交叉淡入建议 0.8—1.6 s，层切换在乐句／小节边界进行。回合交接不重启一整首歌；同章打开抽屉／详情不重新载入音乐。结果判定优先关闭 pulse，再落结算短句，不把 loop 与胜利短曲叠成两个不同调性。

低性能模式只使用一条预混音乐，标准模式最多 3 个 stem；可关音乐但保留战斗和 UI，也可全静音进行完整游戏。

## 9. 可选角色语音与原创台词

战斗语音默认关闭，图鉴可点按试听；玩家开启后仍限密度。语音是角色性格补充，不是理解技能的前提；字面信息由 UI 和字幕承担。先制作少量代表角色，不能将未配音的 32 型号写成已完成全配音。

选中 0.5—1.0 s，技能 0.8—1.3 s，接管／部署 0.7—1.2 s；同单位同类至少 20 s 不重复，全局战斗语音间隔建议 8 s，每个事务最多一条。自动 AI、批量生产／出库默认不发角色台词。重复点击同一头像可预览语音，但第二次点按先停止上一条，不形成叠唱。

| 型号 | 选中／行动／技能可选台词 | 接管／协作可选台词 |
| --- | --- | --- |
| 前哨 | “前哨就位。”／“路口交给我们。” | “灯亮着，继续向前。” |
| 棱镜 | “棱镜，收到。”／“炮架稳定，穿甲装填。” | “我开路，你们跟上。” |
| 浪锋 | “浪锋准备离岸。”／“靠岸，保持队形。” | “港口接通了！” |
| 织补 | “工具都齐了。”／“换好接口，再撑一回合。” | “这条线还能修好。” |
| 纸鸢 | “纸鸢，看得到。”／“扫描已发送。” | “新的坐标，大家收好。” |
| 脉冲 | “联队频道清楚。”／“切换频段，短时干扰。” | “现在，接上我们的线路。” |

前哨没有主动技能，第二句对应实际守备行动；浪锋的第二句对应合法海陆转换。它们不生成新技能事件。其他技能台词只由实际成功的技能触发，按前述语音限频播放。

其他型号以声纹映射的气质写 2—3 句短句即可；保留成年人、专业人员、独立人格的表达。避免所有人都用相同高音“主人”，避免受击喘息和身体痛叫。语音不能宣称永久隐身、全图侦察、复活、护盾无敌、自动拦截等现有规则没有的效果。

默认不配逐次受击／退场台词。若后期添加，仅采用简短“机装脱离”“请求回收”等无线电信息，每 20 s 最多一次，且不能保证角色设定已安全存活。终局台词按公开胜负触发一次，不检查某个唯一剧情人物是否幸存。

配音有字幕、单独开关和单独音量；异步字幕不能阻塞 AP 消耗或事件执行。作品所需录音由授权声优或有合法使用权的原创音色完成，不仿制已有 IP 人物或未经授权的真人声纹。

## 10. 混音、并发与空间信息

以下数值是第一次实机评审的建议目标；最终用实际素材、手机扬声器、耳机及长局听测调整。

### 10.1 分组与响度

建议采用 Master、Battle、Movement、UI、Ambience、BGM、Voice 七组。首次新版迁移可沿用用户主音量，组内默认增益参考 Battle 75%、Movement 45%、UI 65%、Ambience 30%、BGM 40%、Voice 70%；Voice 开关默认关闭。百分比为滑杆初值，不是素材峰值或声压。

- 混音样段离线响度目标约 −18 至 −16 LUFS-I，真峰值不高于 −1 dBTP；需要渲染后测量，不由滑杆数值推断。
- BGM 母带可先以约 −22 至 −20 LUFS-I 为起点；对白约 −19 至 −17 LUFS-I。短枪炮不逐条按 LUFS 强制拉满，先保证瞬态、峰值余量和各类相对响度。
- 重型炮不比常规炮无限更响；建议最多约 +2 至 +3 dB 感知差，更多靠中低频材质、后坐节奏表达。低于约 80 Hz 的无效长尾控制，高频尖锐扫频收短；手机端保留 150—600 Hz 的可听主体和清楚中频瞬态。
- UI 有效确认比普通选择高约 2 dB，失败提示清楚但不刺耳；主音量为零时立即清理动作／环境声，音乐与语音也停止。
- 默认 Master 加轻度动态控制和峰值保护，不能让其每次射击明显抽吸。移动、环境和音乐在战斗密集时先让位。

### 10.2 并发和冷却

建议标准上限为 12 个逻辑声音槽：Battle 6、Movement 2、UI 2、Voice 1、Ambience 1；BGM 另计，最多 3 层。低性能模式建议 8 槽：Battle 4、Movement 1、UI 1、Voice 1、Ambience 1，BGM 单条预混。这是 cue 槽，不是 Web Audio 内部节点数量；一个合成 cue 的振荡器／滤波器等仍要分别清理。

优先级：终局／己方回合明确提示 100 → 实际命中／退场 90 → 技能确认／接管／出库 80 → 武器释放 70 → UI 选择 55 → 移动 30 → 装填余音／环境小细节 10。空间可见性在优先级之前判定；高优先级也不能绕过迷雾。

超限先淡出低优先级移动床或机械尾音，不丢弃当前关键命中与终局结果。短尾淡出目标 15—35 ms，避免硬切产生噼啪。只有已过时的 UI 重复可直接不播放。不得将排队音留到几秒后集中补播。

同类 UI 连点最密 120 ms，invalid 500 ms，deploy.blocked 600 ms；批量 reveal 最密 100—160 ms，多余实例用批次提示。全局每 1 s 对新增战斗瞬态建议软预算 8 次，密集事务选短版、合成退场提示和降低尾音密度；普通攻击和合法反击仍各保留一次关键结果声音。

### 10.3 Ducking 与空间声

语音播出时音乐暂降约 5 dB、环境 3 dB、战斗尾音 2 dB，保持 impact 的主体可辨；约 30—60 ms 进入、200—350 ms 恢复。多层 ducking 取最大衰减，不逐层累加。重点终局／重大设施完成音可让音乐短降 2—3 dB；不为每次步枪声压音乐，避免抽吸。

屏内空间声继续沿当前视图映射，最大声像约 ±0.65。UI、回合和胜负居中；BGM 与环境自然立体声。屏幕外但合法已观测的事件可降低约 3—6 dB并居中或保留很小偏移，不能用可定位远处响声追踪不在观察序列中的实体。提供单声道兼容，双声道相消不能令关键音消失。

迷雾信息约束：

- 完全隐藏的敌方移动、生产、部署、技能不播放；没有方位、型号、数量或节奏暗示。
- 攻击来源不可见而命中可见，只在合法命中位置播放 `hit.unknown`；不播隐藏来源的炮口、充能、飞行、台词，也不从隐藏武器推定声纹。
- 可见路径分段发声；不可见中间段不接长引擎和水声，重新进入可见区时从新的合法段开始，不播放跨迷雾轨迹声。
- 场景／音乐输入只接受合法已知地形和公开章节阶段，不读取完整敌方单位数、库存、资源、路线或未来 AI 指令。
- 缩放、移动镜头和列表重绘不改变已经提交事件的身份，不重复发声。

## 11. 暂停、隐藏、解锁与资源预算

### 11.1 生命周期

1. 首次点击、触摸或键盘操作中的用户手势调用现有 `GameFX.unlock()`。音乐下载／解码可以准备，但不能假定初次进入页面即可发声。解锁失败时界面和战斗照常工作，不弹出阻止游玩的提示。
2. 用户暂停时冻结动作 marker；正在响的短效果可短淡出停止，记录已触发标记而不在恢复时重播。音乐保存循环位置，环境停止；用户恢复后重建仍有效的音乐／环境。游戏暂停与浏览器拒绝恢复音频分别处理。
3. 页面隐藏、设备锁屏、页面离开时停止动作音、环境、语音和音乐，取消未触发但即将过时的调度；返回后只恢复当前合法场景和音乐，不补播后台发生或旧动作残留的枪炮／批量部署。
4. 换战役、读档、重开、热座观察者交接、销毁界面时清空 sessionId、调度、去重表、所有 source／gain／panner 连接，取消待完成的资源回调；旧异步解码完成也不得连上新战局。
5. 运行中 mute／主音量为零，应取消音源而不是只隐藏控制；重新打开仅恢复持续的合法场景，不补播已结束的单次音。分组音量为零仅停止该组。
6. 打开对话／剧情简报时停止战斗环境与动作新调度，使用简报音乐；再次进入战场沿当前章节继续。纯详情抽屉可保持低音量同曲，不能创建第二播放器。

目前 visibilitychange 主要更新环境场景，完整“后台所有分组停声”仍需要开发；不能将它列为已实现。

### 11.2 移动端导出和加载目标

| 项目 | 建议起点 | 验证方式 |
| --- | --- | --- |
| 制作母带 | 48 kHz、24-bit WAV；短战斗／UI 多为单声道，音乐和环境为双声道 | 保存可编辑工程、无削波源文件和授权记录 |
| 运行短音 | 常用 cue 尽量 0.04—0.5 s；编码目标 64—96 kbps 单声道 | 编码后听 transient 是否损坏；格式依实际浏览器验证选择 |
| 运行音乐／环境 | 音乐约 96—160 kbps 双声道；环境约 64—96 kbps | 试听循环边缘、相位、低音量噪声 |
| 编码方案 | 可评估 Opus/Ogg 与 AAC/M4A；必要时另导 MP3 回退 | 按目标 Android／iOS 浏览器及本地启动方式实测，不宣称一种格式通吃 |
| 首次战场音频下载 | 常用效果 + 一条低配音乐合计目标 ≤ 3 MB | 弱网计量；角色语音和完整 7 章按需加载 |
| 常用效果解码缓存 | 建议目标 ≤ 8 MB，整场音频缓存目标 ≤ 24 MB | 统计解码后的 PCM，而不是只看压缩包体；超限释放未使用声族 |
| 单章音乐 | 90—150 s 一条预混或 3 stem；按需加载 | 48 kHz、双声道、Float32 的 120 s PCM 约 46 MB／条，三条不能直接常驻解码缓存 |
| 长音播放 | 优先采用支持长音播放的流式媒体／分段方案，短 cue 用缓冲 | 验证实际格式、加载方式和播放权限；无法可靠分层时使用单条预混 |
| 无缝循环 | 源循环点采样对齐、导出复核；边缘短交叉淡化 | 耳机重复 10 个循环无“嗒”、静音缝或节拍跳动 |
| 资源失败 | 缺采样回退到既有合成 cue；音乐失败静默继续 | 断网／损坏／解码拒绝时无卡住、无重复错误声音 |

解码 PCM 估算式为 `sampleRate × seconds × channels × 4 bytes`。例如 48 kHz、单声道 0.25 s 短音约 48 KB；1 s 双声道约 384 KB。声库几 MB 的压缩文件不等于几 MB 内存。不要在首页一次性解码 38 型号语音与 7 章所有 stem。

建议首轮只预载通用选择、确认、失败、hit.unknown、五类常见 hit 和当前实际可见兵种声族；首次遇到新合法可见单位时异步补载。下载策略不能向用户暴露“正在加载隐藏潜艇”之类文件标签，也不能按隐藏敌方编成预告资源。

## 12. 分期制作、成本与开发交接

本节 P0—P3 是制作阶段代号，不是客服台账的故障优先级。

以下为工作量估算区间，按一个具备音效制作与 Web 音频接入经验的团队、规则基本不改、可使用已有原创合成声作为后备估计；是排期评审输入，不是承诺工期、报价或已完成资产。人民币预算需以团队日成本、作曲／声优授权和设备 QA 费用核算。

| 阶段 | 可审查交付 | 参考工作量 |
| --- | --- | --- |
| P0 风格样板 | 前哨／棱镜／浪锋的移动、发射、命中、部署／接管；一条 60—90 s 原创基础音乐；短／标准声画对照与手机听测 | 音频设计／制作 3—5 人日，接入／调度 2—4 人日，QA 1—2 人日 |
| P1 可玩替换 | 8 移动声族、武器／命中／退场、8 技能、UI／事务提示、4 环境床；38 型号 manifest 全映射，主／分组音量与资源降级 | 制作 8—14 人日，开发 5—8 人日，QA 3—5 人日 |
| P2 世界音乐 | 7 章主题完成或共用主题变奏，菜单／简报／结算，3 层／低配预混，循环和切换测试 | 原创作曲／混音 10—18 人日，开发 3—5 人日，QA 2—4 人日 |
| P3 可选配音 | 先 6 型号 × 3 条 = 18 条；再评估 38 型号每人 2—3 条、字幕及录音一致性 | 先期文本／导演／剪辑 2—4 人日；声优录音、授权与全量扩展另报价 |

P0 可以沿用声音合成快速验证；通过后才制作所有变体。P1 主体预计约 100—160 条运行 SFX（包含选定变体、可复用短版），以最终 manifest 计数为准，不机械生成 38 × 全部动作。完整 7 章 3 stem 即 21 条 stem，另加菜单、简报和结算；低配预混单独导出。合成版、采样版和短版共享语义 cue，避免开发同时维护三套规则映射。

开发任务可拆为：观察序列输出 marker → 音频 manifest／加载后备 → 分组与优先级 → 三档短尾与跳过去重 → 事务／FIFO 汇总 → 音乐及生命周期 → 可选语音。所有效果模块只消费已提交状态，不发命令、不写核心状态、不因音频失败拖延回合。新 API 名称需在实际实现后写入接口说明；本文示例不作已存在函数调用。

## 13. 验收清单与可执行听测

每项记“通过／失败／未测试”、设备、浏览器、素材版本和录屏／日志证据。当前文档完成不等于以下验收已通过。

| 场景 | 合格标准 |
| --- | --- |
| 38 型号抽查与全量清单 | 全部 ID 有合法 cue 或明确后备；轻步兵／主战装甲／舰装／航空／支援声族明显区分，三级不只是越来越响 |
| 8 主动技能 | 每种成功确认只一次；失败不响成功音；scan／jam／repair 闭眼可区分；技能声不宣称规则没有的能力 |
| 标准／快速／减少动态 | launch、impact 与 marker 同步；在 60 fps 录屏中关键音与视觉确认建议误差 ≤ 50 ms；不因模式变换而升调，不重复已触发 cue |
| 纯跳过动画／禁用视觉效果 | 关键命中或成功提示简短一次；合法反击可辨；无整套装填／飞行补播；静音仍能完整理解结果 |
| 移动 → 接管 → FIFO 出库 | 顺序与真实事件一致；部署格未释放不响出库；同一实例不双响；批量合并不漏界面结果 |
| 攻击／退场 → 反击／新部署 | 每一真实结果对应一次；致死合成 cue 不堆三次爆响；无非法反击或虚构援军提示 |
| 迷雾对照 | 构造可见状态完全相同、隐藏编成不同的两局，音频 cue／位置／调度一致；未见来源仅中性命中；环境和 BGM 不泄露隐藏数值 |
| 连点／拖拽／30 分钟对局 | 失败提示和选中不刷屏；移动床不过密；无持续全员引擎；连续玩法耳机／手机均不觉刺耳和疲劳 |
| 分组与旧偏好迁移 | 旧静音保持静音；音乐／语音独立；音量为零清理对应音源；偏好可保存，存档不保存正在播放的节点 |
| 暂停／后台／锁屏／换局 | 停止全部应停分组；恢复不补播过期枪炮；旧异步加载不污染新局；观察者交接不遗留敌方声音 |
| 解锁失败／断网／缺素材 | 游戏命令仍完成；无等待声音完成才能换回合的死锁；安全后备不重复响 |
| 资源与长期清理 | PCM 缓存符合选定档位目标；连续 100 次动作／换场后源节点与连接回到稳定基线，无增长趋势 |
| 音乐／环境循环 | 10 轮循环无突跳；回合不重启主题；层切换、结算不打架；低配预混可用 |
| 响度与单声道 | 混音样段峰值／响度符合批准目标；手机小喇叭能辨关键音；单声道无关键音相消；关闭音乐后 UI 与战斗仍清楚 |

P0 评审建议用一段 45—60 s 固定场景：前哨走两格 → 棱镜普通攻击 → 棱镜穿甲 → 浪锋入海／登陆 → 接管港口 → 实际 FIFO 出库 → 己方回合 → 结算。分别提供标准、快速、减少动态和全静音录屏。之后增加扫描／修复／干扰与隐藏来源命中的专门样段；不能只听一首 BGM 就宣告音画整合完成。

本轮交付的是可进入制作和开发的原创设计规范，未生成、下载或接入第三方音频，也未替换 v0.9 的现有声音。
