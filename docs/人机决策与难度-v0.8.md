# 人机决策与难度 v0.8

本方案用于七个剧情关卡的敌军和自由战役中的 AI 指挥官。所有档位采用相同的移动、射程、反击、生产等级、单位上限和迷雾规则。困难与地狱只根据自身观察范围及建筑的最后观测记录规划行动。

## 四档难度

| 难度标识 | 显示名称 | AI 最大生命 | AI 攻击火力 | AI 基础护甲 | AI 初始金钱、能源及回合收入 | 决策特点 |
| --- | --- | --- | --- | --- | --- | --- |
| `easy` | 简单 | 85% | 85% | 90% | 100% | 基础夺点与进攻；前 8 个己方回合不主动攻击、接管玩家原始总部 |
| `standard` | 标准 | 100% | 100% | 100% | 100% | 优先部署、占领、修复、攻击，保持海陆空扩军与基本能源补充 |
| `hard` | 困难 | 100% | 100% | 100% | 100% | 评估未来火力覆盖、集火与反击代价、安全路线、敌军兵种反制、能源预算 |
| `hell` | 地狱 | 120% | 120% | 110% | 150% | 在困难策略上提高反击风险、协同集火与安全路线权重，同时考虑更多高价值目标 |

倍率只作用于 `controller === 'ai'` 的玩家。人类单位、中立建筑、所有建筑 HP 和护甲、建设与生产价格、升级价格、行动点、航程及射程保持基准规则。AI 同样服从金钱 3000、能源 300、编制 24 的上限。

生命、护甲与资源用 `Math.round` 取整数。初始受损单位按原有生命比例调整，例如 40 / 80 的 AI 步兵在地狱档变为 48 / 96。初始单位、剧情地图预置敌军、设施库存部署和后续生产补充使用同一实例归一流程。剧情敌军继续遵守本关有限生产计划；难度不会新增无限援军或扩大生产白名单。

攻击火力把“基础伤害 + 对兵种/状态加成 + 主动攻击技能加成”整体乘以难度系数并取整，再扣除目标基础护甲及地形掩护，仍保留最低 10 点伤害。防御方的 AI 护甲使用相同实例属性计算。攻击预览、实际伤害和反击共用这套计算；普通反击 50% 与专职防空反击 150% 在计算后的火力上应用一次，最终限制在目标剩余 HP 内。工程修复使用实例 `maxHp`，不会回到图鉴中的基准上限。

## 具体决策

决策区显示当前公开难度、决策阶段与简要说明。实际指令在动画开始前计算一次，随后把这次结果投影到人类观察视角，避免重复计算，也避免泄露隐藏单位和目标。

1. **部署库存**：选择合法设施格或邻格。困难和地狱比较可见敌军的威胁与距离，优先安全部署。
2. **战术行动**：总部接管作为最高价值行动；城市、生产与能源建筑按当前经济价值评分。攻击考虑预期伤害、反击损失、能否击毁、目标受损程度、其他己方部队能否继续攻击，以及炮兵、工程单位的重要性。修复优先拯救重伤单位，干扰优先压制高火力目标。
3. **经济决策**：预估己方已承诺部队的下一回合机动能源消耗。能源不足时优先升级能源设施或建设资源点；生产根据观察到的空军和装甲力量、己方防空数量、工程车缺口、受损部队与能源预算评分。缺少的生产体系与持续收入进入扩建目标。
4. **路线规划**：使用六边形地形真实移动成本计算目标距离。困难比较前三个高价值目标，地狱比较前四个；总部附近出现可见威胁时提高防守目标的重要性。道路、能源、掩护与威胁同时进入路线评分。
5. **保存兵力**：重伤单位处于高威胁且存在明显更安全的位置时，增加撤离权重。炮兵的未来威胁只从静止位置评估，其他兵种评估“一次移动后一次攻击”的可达射击区域。地狱比困难更重视威胁和协同火力。
6. **结束回合**：没有值得执行的可见行动后结束回合；AI 不使用人类玩家的资源、隐藏部队或隐藏建筑变化制定目标。

每一步都使用游戏引擎提交指令，保留占位、反击次数、移动后开火限制、设施等级、生产授权、库存来源和胜利结算规则。固定地图、相同状态和相同难度得到相同指令，不依赖随机抽签。

## 接口

```js
GameAI.difficulties; // 四个难度的 id、name、description 与整数百分比

const raw = GameAI.decision(state);
// { command, phase, phaseLabel, reason, difficulty, scores, threat }
// 只读预判，不改变 state；raw 用于实际提交。

const visible = GameAI.forViewer(state, raw, humanViewerId);
// 保留公开难度；隐藏行动 command=null，说明仅显示“部队调度”。
// 人类观察视角不接收 scores 和 threat 的私人细节。

Game.execute(state, raw.command);

GameAI.choose(state); // 兼容旧接口，仅返回实际 command
GameAI.step(state);   // 兼容旧接口，选择并执行一个动作

Game.unitStats(state, instance); // 实际 HP 上限、基础伤害、护甲等
Game.normalizeUnit(baseUnit, state); // 新生成单位的初始化
Game.tuneUnit(state, instance); // 已有实例的比例归一；重复调用不会叠乘
```

`GameAI.decision(state, viewerId)` 也能直接返回裁剪后的公开结果，但 UI 应优先复用 `forViewer`，只计算一次实际决策。`choose` 为兼容已有流程，会取消失去原设施的旧剧情生产计划；只读展示应使用 `decision`。

## 存档兼容

存档保持 `game-0.7` 容器，新增 `aiDifficultyVersion: 1`。旧 `training` 映射为 `easy`，旧 `challenge` 映射为 `hard`，`standard` 保持不变。没有难度实例版本的旧存档在迁移时按比例调整 AI 生命一次，保留当前资源、AP、冷却、反击次数、生产订单和剧情进度；不会补发地狱初始资源。恢复已有 v0.8 存档不再重复倍率。完整性校验接受难度对应的实例生命上限，并拒绝不匹配的 HP 上限或未知版本。
